# 单租户访问控制（Section 20）

本文件整理单租户（全局）模式下的访问控制设计要点、合规要求与运维检查表。

## 设计原则
- 全局隔离：数据与配置在单一域内统一管理，不存在租户隔离边界。
- 最小权限：RBAC 仅授予必要操作，敏感操作需审批。
- 可追溯：敏感操作必须写入审计。

## 实现要点
- 存储：
  - 使用单一 schema/DSN，所有数据为全局资源。
  - 迁移按全局 schema 执行，记录版本。
- API/Server：
  - 不再需要租户上下文（路径或 header）。
  - CORS/身份认证在 Gateway 层执行，结合 RBAC 控制。
- RBAC：
  - 角色示例：超级管理员、运维管理员、审计员、只读用户、自动化执行者。
  - 权限颗粒度覆盖池/租约/策略/自动化/告警管理。
- 告警与通知：按场景/渠道路由，不进行租户分流。

## 审计要求
- 记录字段：操作者、角色、对象、动作、结果、请求 ID、源 IP、时间。
- 事件范围：配置变更、审批决策、HA 切换、告警抑制、封禁/解封。
- 保留策略：按合规要求设置保留期与脱敏/加密策略。

## 运维检查表
- 每日/每周检查：
  - 审计日志是否完整、未出现写入失败。
  - RBAC 是否与组织角色映射保持同步。
- 变更前：
  - 大规模池/策略变更需有审批与回滚方案。

## 风险与缓解
- 权限滥用：启用审批、最小权限、定期权限审计与双人审查。
- 配置漂移：使用模板化配置与变更审计，必要时启用自动化对账。
