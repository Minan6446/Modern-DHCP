# 存储与 Schema 说明

更新日期：2026-02-10（当前主干）

本文件概述数据库路由、迁移流程与关键表意图，便于排查数据问题或扩展字段。

## 路由与连接
- 单租户：使用单一 DSN/schema；所有数据为全局资源。
- 读写分离：可配置 `readOnly` DSN；写路径仍指向主库。
- 连接池：`maxOpenConns`, `maxIdleConns`, `connMaxLifetime` 控制资源；热点环境需监控等待时间。

## 迁移
- 位置：`migrations/`，使用 SQLx 兼容语法。
- 执行：`go run ./cmd/dbinit --driver mysql --dsn ...`；仅在 Primary 节点执行。
- 顺序：按文件名前缀递增执行；建议迁移不可逆时提供回滚或备份。

## 表意图（摘录）
- 身份与访问：身份提供者、RBAC 角色映射。
- 地址池：分层池定义、权重、容量与元数据（VLAN/接口/Location）。
- 租约：当前与历史租约，包含状态、TTL、设备标识、审计信息。
- 策略与自动化：策略规则、审批流、任务队列与执行日志。
- 告警与通知：阈值、渠道、静默窗口、告警事件。
- 安全：Rate Limit/Snooping 事件与封禁记录。

## 事务与一致性
- 关键写入（租约分配/释放、池调整）使用事务包装，避免部分提交。
- 幂等键：自动化任务与策略发布应携带业务幂等字段，防止重复执行。
- 长事务：避免在热点路径持有长事务；必要时拆分为批处理。

## 性能与索引建议
- 基线索引定义以 [migrations/0001_schema_no_tenant.sql](../migrations/0001_schema_no_tenant.sql) 为准。
- 租约表：关注 `state`/`pool_id` 组合索引与 `expires_at` 覆盖索引，缓解活跃租约计数与分页查询；历史表仍建议分区或归档。
- 池表：按 scope 及 VLAN/接口/SSID/Location 建立索引，加速解析路径；遇到维度组合新增需求时优先评估复合索引复用情况。
- 静态绑定：按 `pool_id` 与 `ip_address` 建立索引支撑按池扫描与冲突校验。
- 审计/事件：高频写入可采用分区或定期归档，避免主表膨胀。
- 维护：部署后执行 `scripts/db/index_maintenance.sql`，刷新统计信息并在低峰期运行 `OPTIMIZE TABLE`，确保优化器尽早选中新索引。

## 数据校验与对账
- 定期校验租约与池容量一致性；对比监控中的池利用率。
- 复制环境校验 binlog 延迟，确保 Secondary 数据新鲜。
- 备份后执行 checksum 或抽样查询，确认可恢复性。
